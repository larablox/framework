# Ограничения roblox-ts, найденные при порте

Всё ниже проверено на скомпилированном Luau (`out/`) и/или выполнением в Studio.
Компилятор не видит семантику Luau — эти вещи не ловятся типами.

## Форма скомпилированного класса

```lua
local Foo
do
    local super = Bar                       -- только если есть extends
    Foo = setmetatable({}, {
        __tostring = function() return "Foo" end,
        __index = super,
    })
    Foo.__index = Foo
    function Foo.new(...)                   -- только для НЕ-abstract класса
        local self = setmetatable({}, Foo)
        return self:constructor(...) or self
    end
    function Foo:constructor(...) ... end
end
```

Отсюда весь `Support/Reflector`:

- `tostring(SomeClass)` возвращает **имя класса** (через `__tostring` метатаблицы).
- `getmetatable(Class).__index` — родительский класс; у корневого класса `nil`.
- Экземпляр отличается от класса тем, что `rawget(getmetatable(v), "__index") == getmetatable(v)`:
  метатаблица экземпляра — это его класс, а `Class.__index == Class`.
- `rawget(Class, "new")` есть только у неабстрактного класса — это и есть
  `ReflectionClass::isInstantiable()`.

**`abstract class X {}` без `extends`** компилируется в голое `X = {}`: ни
метатаблицы, ни `__tostring`, ни `new`. Такой класс не имеет имени в рантайме и
в сообщениях об ошибках печатается как `table: 0x...`.

## Методы

- **Статические методы компилируются как `function Class:method()`** — со скрытым
  `self`, ровно как методы экземпляра. Вызов через индекс всегда должен
  передавать получателя первым: `fn(target, ...)`, независимо от того, класс это
  или экземпляр. Это единственное место, где ошибочное допущение молча ломает
  порядок аргументов.
- **Свойство функционального типа вызывается точкой, метод — двоеточием.**
  `Klass.fn(x)`, где `fn` объявлено как свойство (`declare fn: (v) => r`),
  компилируется в `Klass.fn(x)` без `self`; `Klass.method(x)`, где `method`
  объявлен методом, — в `Klass:method(x)`. Разница определяется формой
  объявления, а не типом: indexed access в метод интерфейса (`Repo["get"]`)
  сохраняет природу метода. Если вызываешь метод через индекс, получателя нужно
  передавать руками: `fn(target, ...)`. Ловилось дважды — на фасадах
  (`Support/Facades/Forwards`, тип `Forwarded<T>`) и на taps в `LogManager`.
- **`constructor` эмитится всегда**, даже если в TS его нет: подкласс получает
  `function Child:constructor(...) super.constructor(self, ...) end`. Поэтому
  «объявлен ли свой конструктор» через `rawget` определить нельзя.
- Обычные методы эмитятся только если объявлены → `rawget(Class, "boot")`
  корректно отличает переопределение от наследования.
- `toString()` в TS маппится на метаметод `__tostring` (используется в
  `Illuminate/Exception`, `Support/Stringable`). Метаметод есть у **каждого**
  скомпилированного класса, поэтому «умеет ли объект в строку» — не вопрос:
  проверять надо класс (так `blank()` ловит `Stringable`).
- Класс, объявленный ниже по файлу, виден методу выше: `local X` поднимается в
  начало модуля, присваивание остаётся на месте. На этом держится
  `Str::of()` — он создаёт `Stringable`, объявленный в конце `Support/Str.ts`.
- Статическое поле и метод экземпляра с одним именем — ошибка компиляции: и то,
  и другое лежит в таблице класса. Отсюда `Container::sharedInstance` вместо
  PHP-шного `$instance` (метод `instance()` — публичный API).

## Декораторы

`experimentalDecorators` поддержан полностью.

- Параметрические декораторы вызываются **всегда**, даже если у класса нет
  собственного декоратора: `transformClassLikeDeclaration` вызывает
  `transformDecorators` безусловно.
- Для параметров конструктора `propertyKey` приходит как `nil`, для параметров
  метода — имя метода. Индекс параметра передаётся третьим аргументом.
- Декоратор класса компилируется в `Class = decorator(Class) or Class`, поэтому
  декоратор, ничего не возвращающий, безопасен.
- `emitDecoratorMetadata` не поддерживается: типов параметров в рантайме нет.
  Отсюда `Container/Attributes/Inject`.

## Трейт — это миксин

Множественного наследования в TypeScript нет, а PHP-класс собирается из
нескольких трейтов сразу. Проверено на компиляторе и прогоном в Studio: миксины
работают, и `this`-типы внутри них тоже.

```ts
export function Conditionable<TBase extends Constructor>(
    Base: TBase = Trait as never,
) {
    return class extends Base {
        public when(value: unknown, callback: (target: this) => unknown): this {
            ...
        }
    };
}

export class Stringable extends Tappable(Conditionable()) {}
```

`use Conditionable, Tappable;` становится `extends Tappable(Conditionable())`,
и трейты складываются в любом порядке и в любой комбинации — жёсткая цепочка
наследования (как `Dispatchable → Queueable → InteractsWithQueue` в Bus) этого
не умеет. Механизм лежит в `Support/Traits/Trait.ts`.

Что при этом надо знать:

- **`Constructor` обязан быть `new (...args: Array<any>) => T`.** Любое сужение
  списка аргументов (`Array<never>`, `Array<unknown>`) даёт TS2545 «A mixin
  class must have a constructor with a single rest parameter of type `any[]`»
  или TS2510 «Base constructors must all have the same return type». `any` в
  проекте запрещён двумя правилами сразу, поэтому в файле стоит
  `/* eslint-disable roblox-ts/no-any, @typescript-eslint/no-explicit-any */`.
  Без обоих `lint:fix` молча перепишет `any` в `unknown` и сломает сборку, а
  директиву на одно правило вычистит как неиспользованную.
- **Каждое применение строит новый класс.** `Conditionable(X)`, вызванный
  дважды, даёт два разных класса, поэтому `instanceof` по трейту бессмысленен —
  спрашивать надо метод. `class_uses_recursive()` в PHP делает ровно это, и его
  здесь тоже нет.
- **Промежуточный класс анонимен**: его `__tostring` возвращает `"Anonymous"`.
  Имя листового класса сохраняется — это то, что печатают сообщения об ошибках
  и `Reflector.className()`, — но обход вверх по `parentClass()` пройдёт через
  безымянные звенья.
- **Классу без родителя нужен корень.** `Conditionable()` без аргумента
  подставляет пустой класс `Trait`: компилятор эмитит в каждый подкласс
  `super.constructor(self, ...)`, и вызывать это должно что-то настоящее.
  `abstract class X {}` без `extends` компилируется в голую таблицу без
  конструктора и на эту роль не годится.
- `private`-метод трейта попадает в таблицу класса как обычный: приватность
  стирается, и одноимённый метод подкласса его перекроет. В PHP у трейтов та же
  беда.

## Типы и стандартная библиотека

- **Массив Luau не хранит `nil`.** `Array<unknown>.push()` не компилируется;
  элементы обязаны быть `defined`. Дыра в массиве обрезает `#`, а значит и
  список аргументов при спреде. Следствия: список зависимостей —
  `Array<defined>`, а `Dispatcher` не кладёт в ответы `nil` от слушателей.
- **Порядок обхода `Map` не определён** (`pairs` по таблице). PHP-массивы
  упорядочены, и фреймворк на это опирается (порядок boot провайдеров). Отсюда
  `Support/OrderedMap`, который лежит под всеми «ассоциативными массивами» порта.
- Слияние namespace не поддерживается — один namespace на файл. В порте вместо
  namespace используются классы со статикой: и линтер доволен, и ближе к PHP.
- `type`, `next`, `error` и `self` — зарезервированные компилятором
  идентификаторы, нельзя использовать как имена переменных и **параметров**.
  `self` ловится на коллбэках трейтов: ``(self) => self.shout()`` не
  компилируется, параметр надо звать иначе. `next` кусается
  особенно: это имя второго параметра middleware в Laravel
  (`handle($passable, $next)`).

  **Конвенция проекта — `_next`.** Проверено: компилируется как есть, с
  временными переменными компилятора (`_exp`, `_binding`) не сталкивается, и
  подчёркивание не глушит `no-unused-vars` — забытый вызов останется ошибкой.
  В аннотациях типа `next` писать можно: имена параметров в типах не эмитятся.

  ```ts
  public handle(job: object, _next: Next): unknown {
      return _next(job);
  }
  ```

  Внутри самого `Pipeline` переменная называется `stack` — так её зовёт и
  `carry()` в Laravel.
- Глобального `Error` нет (только `Promise.Error`) — отсюда `Illuminate/Exception`.
  `throw x` компилируется в `error(x)`, `try/catch` — в `TS.try(...)`, бросать
  можно любой объект, типизированный `catch` выражается через `instanceof`.
- Методов JS-строк нет: только библиотека Luau — `size()`, `sub()`, `find()`,
  `gsub()`, `match()`, `split()`. `find`/`match`/`gsub` возвращают `LuaTuple`,
  который обязан быть деструктурирован (`const [pos] = s.find(...)`).
- Обратная сторона `LuaTuple`: колбэк, чей тип требует его вернуть (например
  преобразование в `DataStore:UpdateAsync`), не примет обычное значение.
  Макрос `$tuple()` для этого и есть, но он разрешён **только как выражение
  `return`** — не в тернарнике, — а `roblox-ts/no-user-defined-lua-tuple` при
  `lint:fix` переписывает его в литерал массива, который к `LuaTuple` из
  `@rbxts/types` уже не приводится. Рабочий приём — описать колбэк своим типом
  и привести его на месте вызова (`transform as never`, см.
  `Cache/DataStoreStore.ts`): скомпилируется он в обычную функцию, а платформе
  ровно это и нужно.
- `@rbxts/types` объявляет `GetAsync`/`SetAsync`/`UpdateAsync`/`RemoveAsync`
  как `unknown` на `GlobalDataStore`, а типизированные версии — на `DataStore`.
  Аннотация `GlobalDataStore` у своего геттера обрубает типы; пишите
  `store(): DataStore`.
- Массив и таблица-класс в рантайме неразличимы напрямую; `Util.isArray`
  отличает их по `#value > 0`, поэтому **пустой массив считается одиночным
  значением**. Там, где пустой список законен (`Pipeline.through([])`,
  `Queueable.through()`), проверка другая: у обычной таблицы нет метатаблицы, а
  у класса и у экземпляра она есть. Ошибка обходится дорого — `through([])`
  клал пустую таблицу в список пайпов, и контейнер пытался её инстанцировать.

## Циклический импорт значения убивает модуль

`import type` стирается и безопасен; импорт **значения** по кругу — нет.
`TS.import` вызывает `require` на середине загрузки первого модуля, и Roblox
отвечает `Requested module experienced an error while loading` — падает весь
модуль, а не одна строка, поэтому сообщение указывает мимо причины.

Так `Cache/MemoryStoreStore` и `Cache/MemoryStoreLock` заклинили друг друга:
стор импортировал лок ради `new`, а лок импортировал из стора константу.
Лечится в одну сторону — константу отдаёт метод (`store.maxExpiration()`), а
обратный импорт остаётся `import type`. Ищется требованием модулей по одному в
Studio: первый, который не загрузился, и есть звено цикла.

Когда развернуть в одну сторону нельзя — `Str::of()` создаёт `Stringable`, а
каждый метод `Stringable` зовёт `Str` обратно, — остаётся один модуль на два
класса: оба лежат в `Support/Str.ts`, а файл по PHP-шному пути
(`Support/Stringable.ts`) только реэкспортирует класс.

## Паттерны Luau вместо PCRE

Регулярных выражений нет — только паттерны Luau. Чего в них нет:

- **альтернатива** `a|b` — каждый вариант приходится выносить в отдельный
  паттерн (так устроены правила в `Support/Pluralizer`);
- **квантификатор над группой**: `(%s)+` не работает, `+` применим только к
  одному символу или классу. Повторяющийся многосимвольный префикс/суффикс
  снимается циклом — см. `Str::start` и `Str::finish`, которые в PHP написаны
  как `preg_replace('/(?:...)+$/')`;
- lookaround и нежадные квантификаторы.

Магические символы паттерна — `^$()%.[]*+-?`, экранируются через `%`.

`string.lower`/`string.upper` работают только с ASCII: кириллица и латиница с
диакритикой не сворачиваются. Длина и подстроки при этом могут быть корректными
по кодпоинтам — через `utf8.len` и `utf8.offset`.

## rbxtsc не проверяет свой вывод

`rbxtsc` валидирует только типы TypeScript. Он способен выдать Luau, который не
парсится, и сообщить об успешной сборке: так один NUL-байт, попавший в
шаблонную строку исходника, превратился в `` `{value}\0{delimiter}` `` и сломал
интерполяцию. Компилятор промолчал, `npm run analyze` показал
`SyntaxError: Malformed interpolated string`.

Отсюда правило: `npm run analyze` — не опциональная проверка, а единственное,
что читает сгенерированный Luau как код.

## Studio и кэш модулей

`require` кэширует модуль по экземпляру `ModuleScript`, а Rojo обновляет
`Source` на месте — в Edit-режиме изменённый код **не подхватывается**. Чтобы
проверить свежий код без перезапуска Studio, нужно подменить дерево целиком:

```lua
origFw.Name = "__fw_orig"
local fw = origFw:Clone(); fw.Name = "Illuminate"; fw.Parent = rs
-- ... require(fw. ...) видит свежие модули ...
fw:Destroy(); origFw.Name = "Illuminate"
```

Ещё две вещи про этот цикл:

- **Rojo синхронизирует Edit, а Play снимает с него копию на старте.** Сборка
  во время запущенного Play в игру не попадёт: после `npm run build` надо
  остановить и снова запустить Play, и только потом делать подмену клонами.
- **`npm run clean` удаляет `include/`**, а он прописан в
  `default.project.json` — запущенный `rojo serve` в этот момент падает
  (`Canonicalize … include`). Порядок такой: `npm run clean && npm run build`,
  и только после сборки поднимать `rojo serve`.
